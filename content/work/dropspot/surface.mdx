DropSpot's interface groups seven real routes into five areas, not a single dashboard trying to do everything: Home (browsing drops as cards), Drop Detail (one drop's waitlist/claim actions), Auth (separate sign-up and login forms), My Account (My Waitlist and My Claims), and an admin-only CRUD panel behind its own route guard. Every drop card and the detail page repeat the same status badge — upcoming, active, or ended — computed from the drop's claim window, so a visitor never has to guess whether a drop is currently claimable.

The Drop Detail page's action area changes shape depending on where the visitor actually stands, not just what they're allowed to click: signed-out visitors see a prompt to log in; a signed-in visitor not yet in the waitlist sees "Join Waitlist"; someone already in the waitlist but outside the claim window sees a confirmation and a "Leave Waitlist" option instead of a disabled claim button; and once the window is open, the same slot becomes "Claim Now!" (or "Out of Stock" if the last unit is gone). Three stat tiles — available stock, waitlist count, claimed count — sit above the action area on both the card and the detail page, so the numbers a visitor is deciding against are always visible, not hidden behind a click.

Authentication and authorization are both real gates, not visual-only ones: React Router wraps `/my-waitlist`, `/my-claims`, and `/admin` in a route guard that checks an auth token and, for `/admin`, a decoded `admin` role before rendering anything, redirecting to `/login` or `/` otherwise — matching the same role check the backend independently enforces on every admin API call. The admin panel itself is a separate table view, not a repurposed version of the public drop cards.
