6. B — PROJECT SCENE GRAMMAR
==================================================

Current project transitions remain visually weak.

Observed symptoms include:

- project titles entering clipped at viewport edges
- outgoing/incoming projects visible in awkward partial states
- huge dead space between foreground objects
- ghost typography overlapping without purpose
- background planes reading as beige rectangles/cards
- project acquisition not feeling deliberate
- project departure not feeling deliberate
- diagrams too small to communicate evidence
- real screenshots and diagrams carrying inconsistent visual weight
- DropSpot accidentally dominating because of its colorful screenshot
- Software Factory not reading as project 01 / foundational
- OPEN CASE STUDY action too weak
- SURFACE / FLOW / SYSTEM mostly remaining labels rather than an experience

Rebuild the project scene grammar coherently.

Each project should have a readable state progression:

DETECTED
→ ACQUIRED
→ FOCUSED
→ UNDERSTOOD
→ RELEASED

Names may differ internally, but the visual behavior must communicate those states.

At FOCUS:

- project identity must be unmistakable
- primary evidence must be legible
- hierarchy must be clear
- neighboring projects must not contaminate composition
- CTA must be discoverable
- unnecessary background typography must not compete

==================================================

NEW OWNER FINDING:

DO NOT fix this with an arbitrary lower-world velocity multiplier.

Preserve the principle of ONE coherent global scroll physics system.

2. compact empty/dead travel

vertical

But PERCEIVED PROGRESS must be much faster in the lower world.
